# edway.space

Школьная платформа тестирования

Конструктор тестов для учителя: работа собирается в визуальном редакторе, печатается вместе с бланком ответов, а после урока сканируется — закрытые задания платформа проверяет сама, развёрнутые остаются учителю. Оценки складываются в журнал по дате, классу и тесту.

## Стек

- Фронтенд: TypeScript, Next.js 16, React 19, TailwindCSS 4, sweetalert2-neutral, Chart.js, TipTap, KaTeX (интерфейс — на основе шаблона NightingaleUI)
- Бэкенд: TypeScript, NestJS 12 на Fastify, Prisma 7, sharp, tesseract-ocr
- СУБД: PostgreSQL 18
- Сервер: Caddy, Docker

## Как это устроено

Ученики не заходят на платформу — они пишут на бумаге. Учитель собирает тест, назначает его классу на дату и печатает пачку листов: лист с заданиями и бланки ответов, по одному на ученика. Фамилия и код работы уже напечатаны на бланке, поэтому распознавать почерк в подписи не нужно — только сами ответы.

После урока листы сканируются и загружаются пачкой. Каждый лист сам говорит, чей он: в углу напечатан код работы. Платформа выравнивает скан по четырём чёрным меткам в углах, режет клетки ровно по той разметке, по которой лист печатался, и распознаёт написанное. Ответы сверяются с ключом, баллы складываются, по шкале выставляется оценка.

Требование к почерку одно, зато жёсткое: **буквы и цифры печатные, крупные, по одному знаку в клетке**. Прописной почерк OCR не читает.

## Возможности

- **Конструктор тестов.** Задания четырёх типов: один вариант, несколько вариантов, краткий ответ и развёрнутый. Текст задания набирается в визуальном редакторе — полужирный, курсив, списки, картинки (чертежи, графики, схемы) и математические формулы.
- **Формулы.** Формула вставляется прямо в текст задания и правится там же; синтаксис LaTeX, рядом предпросмотр и полтора десятка заготовок (дробь, корень, степень, сумма, интеграл, система). Хранится исходный LaTeX, поэтому формула одинаково выглядит в конструкторе, на печатном листе и на странице проверки.
- **Ключи проверки.** Для выбора — отмеченные верные варианты и режим частичного зачёта. Для краткого ответа — несколько допустимых написаний, числовой режим с допуском («2.71 ± 0.01»), регистр и «ё» платформа приводит сама. Для развёрнутого — критерий, который виден при проверке.
- **Шкала оценок** задаётся в процентах от максимума и замораживается в момент назначения.
- **Классы и списки учеников.** Список вставляется колонкой из журнала. Ушедшие из списка ученики уходят в архив вместе со своими оценками, вернувшиеся — восстанавливаются. Одна кнопка переводит всю школу на следующий учебный год.
- **Назначения.** Тест, класс и дата. Платформа сразу заводит по бланку на каждого ученика плюс запасные — для новеньких и вместо испорченного листа.
- **Печать.** Лист с заданиями и бланки ответов, миллиметр в миллиметр по разметке распознавания.
- **Проверка.** Скан работы показывается рядом с разобранными ответами: любой ответ можно переписать, засчитать вручную или снять, а развёрнутым выставить баллы. Всё, что платформа прочитала неуверенно, помечено.
- **Журнал оценок** с фильтрами по дате, классу и тесту, сводкой (средний балл, качество знаний, успеваемость) и выгрузкой в CSV.
- **Общий доступ.** Тестом можно поделиться с коллегой из списка — только для чтения или с правом правки.
- **Оформление.** Тёмная и светлая темы, шесть акцентных цветов.

## Бланк ответов

Бланк — обычный лист A4, но с жёсткой геометрией: её задаёт сервер, и по ней же режется скан.

```
┌─■──────────────────────────────────── ■─┐   ■ — метки выравнивания (8 мм)
│  EDWAY.SPACE · БЛАНК ОТВЕТОВ  A7K2-9QF3/1│   код работы и номер страницы
│  Контрольная по дробям                   │
│  8Б · 10 сентября 2026                   │
│  Иванов Пётр                             │
│  ─────────────────────────────────────── │
│  1  [Б]                 одна буква: А, Б │
│  2  [А][В][ ]      буквы верных вариантов│
│  3  [3][/][4][ ][ ][ ]   по знаку в клетке│
│                                          │
└─■──────────────────────────────────── ■─┘
```

Печатать нужно в масштабе 100%, без «вписать в страницу», и не обрезать углы: по четырём меткам платформа находит сетку листа, поэтому наклон, сдвиг и небольшой перекос при сканировании ей не мешают.

Развёрнутые задания в бланк не попадают — они пишутся на обороте, а внизу листа перечислено, какие именно.

## Что делать, если лист не распознался

Такое бывает: смятый угол, слишком светлая печать, обрезанная метка. Платформа не выбрасывает такой скан, а показывает его отдельно и предлагает привязать к работе вручную. Дальше ответы можно вписать руками — конвейер проверки от этого не зависит, автоматика лишь экономит время.

Если на сервере нет tesseract, платформа честно скажет об этом в `/api/health` (`"ocr": "unavailable"`) и продолжит работать в ручном режиме.

Разбирать, почему конкретный лист прочитался плохо, помогает переменная `OCR_DEBUG_DIR`: если её задать, платформа оставит в этом каталоге выровненный лист и все нарезанные клетки — по ним сразу видно, дело в скане или в распознавании.

## Учётные записи и вход

Платформа селфхостная и стоит внутри школы, поэтому регистрация свободная и никакого администратора в ней нет. Учитель вводит фамилию и имя, выбирает предмет и придумывает пароль; логин платформа собирает транслитом («Наземнова Наталья» → `nazemnova.n`) и показывает один раз после регистрации — его и нужно запомнить.

Сессия живёт долго (по умолчанию 90 дней), список активных устройств виден в настройках, любую сессию можно завершить.

Тесты, назначения и оценки привязаны к учителю: чужие работы в списке не появляются, пока автор не поделится тестом. Классы и списки учеников — общие для школы: их ведут все вместе.

## Запуск в Docker

```bash
cp .env.example .env
docker compose up -d --build
```

Не забудьте подставить свои значения переменных в .env.

Платформа будет доступна по адресу http://localhost:8020. Изменить порт можно через переменную "HTTP_PORT", а интерфейс публикации — через "HTTP_BIND" (по умолчанию 127.0.0.1, то есть снаружи платформа доступна только через Caddy).

Порт по умолчанию именно 8020: на школьном сервере 8000 занимает ЦСУАМ «Архивли», а 8010 — «Психолоджик».

Переменная "PUBLIC_URL" — публичный адрес платформы. По его схеме определяется флаг Secure у cookie сессии. Если указать https, а открыть платформу по http, Safari молча выбросит cookie: вход пройдёт, но все следующие запросы вернут 401.

При первом запуске автоматически применяются миграции. Учётную запись учитель заводит сам на странице `/register`.

Стек состоит из четырёх контейнеров: PostgreSQL, API на NestJS, интерфейс на Next.js и Caddy перед ними — он же отдаёт страницы ошибок. Сканы работ и картинки заданий лежат в отдельном томе `uploads`, а не в базе.

## Запуск в проде

Развёртывание на Debian Linux полностью автоматизировано скриптом "deploy.sh":

```bash
cp deploy.conf.example deploy.conf
nano deploy.conf
sudo ./deploy.sh
```

Скрипт устанавливает Docker и Caddy из официальных репозиториев, при необходимости отключает nginx и certbot (конфигурация сохраняется в резервную копию), генерирует .env со случайными паролями, собирает и запускает контейнеры, настраивает Caddy и получает сертификат Let's Encrypt. Повторный запуск обновляет платформу: скрипт идемпотентен, ранее сгенерированные пароли сохраняются, а перед обновлением снимаются дамп базы и архив загруженных сканов.

Полезные ключи:

- "sudo ./deploy.sh --check" — проверить конфигурацию, DNS и занятость портов, ничего не меняя;
- "sudo ./deploy.sh --skip-packages" — не трогать apt-пакеты;
- "sudo ./deploy.sh --config /путь/deploy.conf" — другой файл конфигурации.

Все параметры (домен, почта для сертификата, режим TLS, каталог установки, пароли, срок жизни сессии, фаервол, резервные копии) описаны в deploy.conf.example.

Скрипт отдельно проверяет, что порт приложения не занят другой платформой: если на 8020 уже отвечает чужой контейнер, развёртывание остановится, а не отправит домен в чужое приложение.

Сертификаты выпускает и продлевает сам Caddy, certbot не нужен. Хостовая конфигурация генерируется в /etc/caddy/conf.d/edway.caddy, её образец — caddy/edway.caddy.example.

## Страницы ошибок

Страницы 401, 403, 500 и 502 лежат в frontend/public/errors. Их отдают оба уровня: Caddy внутри стека — при ошибках приложения, хостовой Caddy — при своих (например, когда стек не отвечает; deploy.sh копирует страницы в /var/www/edway-errors). Прочие ошибки 5xx показывают страницу 500. Ответы API остаются в JSON: HTML-страница подставляется только тогда, когда запрос пришёл из адресной строки браузера (заголовок Accept содержит text/html), поэтому fetch-клиент продолжает получать {"message": "…"}.

## Разработка

Бэкенд (Node.js 24+, PostgreSQL 18, tesseract-ocr с русским языком):

```bash
cd backend
cp .env.example .env          # подставьте DATABASE_URL и JWT_SECRET
npm install
npx prisma migrate dev        # создаст и накатит миграции
npm run dev                   # http://localhost:3000/api
```

Фронтенд:

```bash
cd frontend
npm install
npm run dev                   # http://localhost:3001, /api проксируется на :3000
```

Для распознавания нужен tesseract с русским языком: `apt install tesseract-ocr tesseract-ocr-rus` или `brew install tesseract tesseract-lang`. Без него платформа работает, но проверяет только вручную.

Проверки:

```bash
npm run type-check            # оба пакета разом
npm run test:e2e              # сквозные сценарии Playwright
```

Сценарии гоняются против уже поднятого стека (по умолчанию http://127.0.0.1:3001); другой адрес задаётся переменной "E2E_BASE_URL". Набор проверяет вход и регистрацию, путь «класс → тест → назначение → бланки → проверка → журнал» и распознавание: тест вписывает знаки в клетки напечатанного бланка, снимает лист и отправляет его как скан — ответы должны вернуться с сервера разобранными.

## Модель данных

```
Teacher ──< AuthSession        учителя и их долгие сессии
        ──< Test ──< Question  тесты с заданиями и ключами проверки
                 ──< TestShare доступ коллегам
        ──< MediaFile          картинки в текстах заданий

SchoolClass ──< Student
            ──< Assignment >── Test
                          ──< Work ──< ScanPage
```

Назначение хранит снимок теста: задания, ключи и шкалу оценок на момент выдачи. Поэтому правка теста задним числом не переписывает уже проверенные работы — прошлогодняя контрольная так и остаётся прошлогодней.

Ученик, ушедший из списка класса, не удаляется, а уходит в архив: его работы и оценки остаются в журнале. Класс с историей при переводе (7Б → 8Б) тоже не переименовывается — заводится новая запись, а прежняя уходит в архив со своими результатами.

## Безопасность

- Пароли хешируются scrypt (входит в состав Node, нативные зависимости не нужны).
- JWT лежит в httpOnly-cookie, сессии учитываются в базе и отзываются по одной или все сразу.
- Вход и регистрация ограничены по частоте запросов — перебор пароля упирается в лимит.
- Сканы работ и картинки заданий отдаёт API, а не веб-сервер: каталог загрузок лежит в приватном томе и доступен только вошедшим.
- Чужой тест виден, только если автор поделился им явно; править его можно, лишь когда автор дал такое право.
