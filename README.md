# edway.space

Школьная платформа тестирования

Учитель собирает проверочную работу в конструкторе, печатает комплекты бланков и сканирует написанное — закрытые задания платформа проверяет сама и выставляет оценки по школьной шкале. Ученики пишут ручкой на бумаге, как и раньше.

Платформа обслуживает много школ сразу: каждая работает в своих границах и платит за подписку.

## Стек

- Фронтенд: TypeScript, Next.js 16, React 19, TailwindCSS 4, sweetalert2-neutral, Chart.js, TipTap, KaTeX (интерфейс — на основе шаблона NightingaleUI, как в ЦСУАМ и «Психолоджике»)
- Бэкенд: TypeScript, NestJS 12 на Fastify, Prisma 7, sharp, tesseract-ocr
- СУБД: PostgreSQL 18
- Оплата: ЮKassa
- Сервер: Caddy, Docker

## Как это устроено

Школа — граница всего. Классы, тесты, назначения, работы и оценки принадлежат ей, и запрос за её пределы не выходит даже по прямой ссылке на чужой идентификатор. Сотрудник одной школы не увидит данные другой ни в списке, ни по адресу файла.

Ученики учётных записей не имеют: они пишут на бумаге. Учитель печатает бланки с фамилиями и кодами работ, после урока сканирует листы и загружает их пачкой — каждый лист сам находит своего ученика по коду в углу.

## Роли

| Роль | Что делает | Второй фактор |
|---|---|---|
| Администратор платформы | Заводит школы, продлевает и закрывает доступ, видит платежи. Учебных данных школ не видит | обязателен |
| Администратор школы | Заводит учителей, платит за подписку, ведёт свои классы | обязателен |
| Учитель | Классы, тесты, назначения, проверка работ, журнал оценок | по желанию |

Свободной регистрации учителей нет. Школа появляется двумя путями: директор регистрирует её на сайте и получает две недели знакомства либо оплачивает год сразу. Учителей заводит уже администратор школы; каждому выдаётся логин транслитом и временный пароль.

Первым делом учётная запись проходит настройку: смена временного пароля, а для администраторов — подключение второго фактора (Google Authenticator, Яндекс.Ключ, Aegis). До её окончания API не отдаёт данных вовсе.

## Подписка и оплата

Тариф один: **14 900 ₽ за год** для школы целиком, без ограничения числа учителей, классов, работ и учеников.

- **14 дней бесплатно.** Школа заводится сразу после регистрации и работает полностью — успеете провести настоящую контрольную и посмотреть, как платформа читает почерк ваших учеников. Карта не нужна.
- **Оплата картой** через ЮKassa, чек приходит на почту. Оплаченные заранее дни не сгорают: срок прибавляется к остатку.
- **Данные не удаляются.** Когда подписка кончилась, кабинет открывает страницу продления, а классы, тесты, работы и журнал ждут на месте. После оплаты всё возвращается.

Уведомлению кассы платформа не верит на слово: подписи у ЮKassa нет, поэтому статус платежа подтверждается встречным запросом к её API. Повторные уведомления (касса шлёт их, пока не получит 200) подписку дважды не продлевают.

Пока ключи магазина не заданы, касса работает **в учебном режиме**: путь оплаты проходится целиком, но денег не двигает. Так платформу разворачивают и проверяют до подключения кассы.

Адрес для уведомлений в кабинете ЮKassa: `https://ваш-домен/api/billing/webhook`

## Возможности

- **Конструктор тестов.** Задания четырёх типов: один вариант, несколько вариантов, краткий ответ и развёрнутый. Текст набирается в визуальном редакторе — полужирный, курсив, списки, картинки и математические формулы.
- **Формулы.** Больше сотни заготовок по разделам — дроби и степени, алгебра, геометрия, тригонометрия, начала анализа, множества и логика, физика с химией. Заготовка ищется по названию и встаёт туда, где стоит курсор. Хранится исходный LaTeX, поэтому формула одинаково выглядит в конструкторе, на печатном листе и на странице проверки.
- **Ключи проверки.** Для выбора — отмеченные верные варианты и режим частичного зачёта. Для краткого ответа — несколько допустимых написаний, числовой режим с допуском, регистр и «ё» платформа приводит сама. Для развёрнутого — критерий, который виден при проверке.
- **Варианты.** До четырёх вариантов в одной работе: задание помечается своим номером или остаётся общим. Ученики получают варианты по списку класса подряд — соседям по парте достаются разные. Тест с вариантами разной стоимости платформа не публикует: шкала оценок одна на всех.
- **Классы и списки учеников.** Список вставляется колонкой из журнала. Ушедшие ученики уходят в архив вместе со своими оценками, вернувшиеся — восстанавливаются. Одна кнопка переводит всю школу на следующий учебный год.
- **Печать комплектами.** На каждого ученика — свой комплект подряд: лист с заданиями его варианта, бланк ответов и лист под развёрнутый ответ.
- **Проверка.** Скан работы показывается рядом с разобранными ответами: любой ответ можно переписать, засчитать вручную или снять. Всё, что платформа прочитала неуверенно, помечено.
- **Разбор заданий.** После проверки видно, с каким заданием класс не справился.
- **Журнал оценок** с фильтрами по дате, классу и тесту, сводкой (средний балл, качество знаний, успеваемость) и выгрузкой в CSV.
- **Общий доступ.** Тестом можно поделиться с коллегой из своей школы — только для чтения или с правом правки. Оценки при этом видит лишь тот, кто проводил работу.
- **Установка на устройство.** Платформа ставится как приложение: свой значок, запуск без адресной строки. Без сети вместо ошибки браузера открывается понятная страница.

## Бланк ответов

Бланк — обычный лист A4, но с жёсткой геометрией: её задаёт сервер, и по ней же режется скан.

```
┌─■──────────────────────────────────── ■─┐   ■ — метки выравнивания (8 мм)
│  EDWAY.SPACE · БЛАНК ОТВЕТОВ  A7K2-9QF3/1│   код работы и номер страницы
│  Контрольная по дробям                   │
│  8Б · 10 сентября 2026 · вариант 1       │
│  Иванов Пётр                             │
│  ─────────────────────────────────────── │
│  1  [Б]                 одна буква: А, Б │
│  2  [А][В][ ]      буквы верных вариантов│
│  3  [3][/][4][ ][ ][ ]   по знаку в клетке│
│                                          │
└─■──────────────────────────────────── ■─┘
```

Требование к почерку одно: **буквы и цифры печатные, по одному знаку в клетке**. Печатать нужно в масштабе 100% и не обрезать углы — по четырём меткам платформа находит сетку листа, поэтому наклон и небольшой перекос при сканировании ей не мешают. Галочка «фоновая графика» в диалоге печати не нужна: метки нарисованы векторной фигурой, а не заливкой.

Развёрнутые задания в клетки не помещаются — для них печатается отдельный лист с теми же метками и кодом, и отсканированный он сам находит свою работу.

## Если лист не распознался

Такое бывает: смятый угол, слишком светлая печать, обрезанная метка. Платформа не выбрасывает такой скан, а показывает его отдельно и предлагает привязать к работе вручную. Дальше ответы вписываются руками — конвейер проверки от автоматики не зависит, она лишь экономит время.

Разбирать, почему конкретный лист прочитался плохо, помогает переменная `OCR_DEBUG_DIR`: платформа оставит в этом каталоге выровненный лист и все нарезанные клетки.

## Документы

Пользовательское соглашение и политика обработки персональных данных лежат на `/legal/terms` и `/legal/privacy`, ссылки — в подвале сайта. Реквизиты оператора задаются переменными окружения и вшиваются в страницы при сборке фронтенда.

Разделение ролей по 152-ФЗ такое: оператором данных обучающихся выступает школа, платформа обрабатывает их **по её поручению** (ч. 3 ст. 6) и только для работы сервиса. Собственных целей обработки этих данных у платформы нет.

## Запуск в Docker

```bash
cp .env.example .env
docker compose up -d --build
```

Платформа поднимется на http://localhost:8020. Порт меняется переменной `HTTP_PORT`, интерфейс публикации — `HTTP_BIND` (по умолчанию 127.0.0.1, то есть снаружи платформа доступна только через Caddy).

Порт по умолчанию именно 8020: на том же сервере могут работать ЦСУАМ «Архивли» (8000) и «Психолоджик» (8010).

При первом запуске применяются миграции и создаётся администратор платформы. Логин берётся из `ADMIN_LOGIN`, пароль — из `ADMIN_PASSWORD`; если пароль не задан, он генерируется и выводится в журнал:

```bash
docker compose logs backend | grep -A5 "администратора платформы"
```

Потеряли доступ администратора платформы — сбрасывать его некому, поэтому есть скрипт:

```bash
cd backend && npm run admin:reset
```

Стек состоит из четырёх контейнеров: PostgreSQL, API на NestJS, интерфейс на Next.js и Caddy перед ними — он же отдаёт страницы ошибок. Сканы работ и картинки заданий лежат в отдельном томе `uploads`, а не в базе.

## Запуск в проде

Развёртывание на Debian автоматизировано скриптом `deploy.sh`:

```bash
cp deploy.conf.example deploy.conf
nano deploy.conf
sudo ./deploy.sh
```

Скрипт устанавливает Docker и Caddy, при необходимости отключает nginx и certbot, генерирует .env со случайными паролями, собирает и запускает контейнеры, настраивает Caddy и получает сертификат Let's Encrypt. Повторный запуск обновляет платформу: скрипт идемпотентен, ранее сгенерированные пароли сохраняются, а перед обновлением снимаются дамп базы и архив загруженных сканов.

Полезные ключи:

- `sudo ./deploy.sh --check` — проверить конфигурацию, DNS и занятость портов, ничего не меняя;
- `sudo ./deploy.sh --skip-packages` — не трогать apt-пакеты;
- `sudo ./deploy.sh --config /путь/deploy.conf` — другой файл конфигурации.

Ключи ЮKassa, стоимость подписки и реквизиты оператора задаются в `deploy.conf` — оттуда они попадают и в .env, и в сборку фронтенда.

## Разработка

Бэкенд (Node.js 24+, PostgreSQL 18, tesseract-ocr с русским языком):

```bash
cd backend
cp .env.example .env          # подставьте DATABASE_URL и JWT_SECRET
npm install
npx prisma migrate dev
npm run dev                   # http://localhost:3000/api
```

Фронтенд:

```bash
cd frontend
npm install
npm run dev                   # http://localhost:3001, /api проксируется на :3000
```

Для распознавания нужен tesseract с русским языком: `apt install tesseract-ocr tesseract-ocr-rus` или `brew install tesseract tesseract-lang`. Без него платформа работает, но проверяет только вручную.

Проверки:

```bash
npm run type-check            # оба пакета разом
npm run test:e2e              # сквозные сценарии Playwright
```

Сценарии гоняются против уже поднятого стека (по умолчанию http://127.0.0.1:3001); другой адрес задаётся переменной `E2E_BASE_URL`. Набор проверяет витрину и документы, регистрацию школы с обязательной настройкой входа, границы между школами (включая доступ к файлам), оплату и продление, панель платформы, путь «класс → тест → назначение → бланки → проверка → журнал», варианты, весь набор заготовок формул, установку на устройство и распознавание — в том числе через настоящую печать в PDF без фоновой графики.

На стенде, где проверки гоняются десятками подряд, поднимите пороги `LOGIN_RATE_LIMIT` и `REGISTER_RATE_LIMIT`.

## Модель данных

```
School ──< Account ──< AuthSession        школы, их сотрудники и сессии
       │            ──< BackupCode        резервные коды второго фактора
       ──< Payment                        платежи ЮKassa
       ──< SchoolClass ──< Student
       ──< Test ──< Question              задания, ключи и варианты
                ──< TestShare             доступ коллегам
       ──< Assignment ──< Work ──< ScanPage
```

Назначение хранит снимок теста: задания, ключи и шкалу оценок на момент выдачи. Поэтому правка теста задним числом не переписывает уже проверенные работы.

Ученик, ушедший из списка класса, не удаляется, а уходит в архив: его работы и оценки остаются в журнале. Класс с историей при переводе (7Б → 8Б) тоже не переименовывается — заводится новая запись, а прежняя уходит в архив со своими результатами.

## Безопасность

- Пароли и резервные коды хешируются scrypt (входит в состав Node, нативные зависимости не нужны).
- Второй фактор по TOTP обязателен для администраторов платформы и школ; резервные коды одноразовые.
- JWT лежит в httpOnly-cookie, сессии учитываются в базе и отзываются по одной или все сразу. Закрытие школы обрывает сессии её сотрудников.
- Вход, регистрация школы и оформление оплаты ограничены по частоте запросов.
- Данные каждой школы обособлены на уровне запросов: школа стоит в условии выборки, а не проверяется постфактум. Сканы и картинки заданий отдаются только своей школе — имя файла ничего не открывает.
- Администратор платформы не имеет доступа к учебным данным школ: API отвечает ему отказом по роли.
